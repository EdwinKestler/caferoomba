## Evidence by judging theme

| Theme | Supported material | Boundary |
|---|---|---|
| Technical approach | Offline teacher/onboard student architecture; typed intents; safety/FSM design | Live teacher and complete autonomous mission are not verified |
| Technology use | Public CPU PyTorch/ONNX code; target Jetson; historical private GCS storage record | CPU inference is not GPU deployment; storage is not Colab training |
| Usefulness | Coffee-patio sweeping use case and owner-provided physical-prototype media | No measured labor savings, drying-quality gain, yield or ROI |

## Publication discipline

Do not say “fine-tuned Cosmos,” “trained in Colab Enterprise,” or “deployed the learned policy on Jetson” until actual records support those statements. The current live teacher refuses execution and its annotations are not wired into the public trainer.

Keep historical prototype dates, software revisions, learning completion, site publication and later tests distinct. Never backdate code or later execution evidence to an entry deadline. Contest rules and eligibility are determined by the organizers, not by this repository.
